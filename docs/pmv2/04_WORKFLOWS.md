# Workflows — PM V2

## Workflow A — إنشاء برنامج صيانة

الإدارة:

**اختيار المواقع → اختيار الفريق → اختيار Checklist → تاريخ البداية → تفعيل**

---

## Workflow B — توليد مهام اليوم

Scheduler:

**فحص البرامج الفعالة → حساب البنود المستحقة → تجميع حسب الموقع والفريق → إنشاء مهمة واحدة → Snapshot للبنود**

يجب أن يكون Idempotent ولا ينشئ Duplicate.

---

## Workflow C — تنفيذ الفني

**مهامي اليوم → الموقع → البند 1 → اختيار النتيجة → التالي → حتى آخر بند → إنهاء الزيارة**

---

## Workflow D — سليم

**سليم → حفظ النتيجة → التالي**

---

## Workflow E — تم الإصلاح بدون مادة

**تم الإصلاح → هل استخدمت قطعة؟ لا → حفظ → التالي**

---

## Workflow F — تم الإصلاح بمادة

**تم الإصلاح → نعم → اختيار صنف من مخزن الفريق → كمية → تنفيذ نفس حركة المخزون/المستودع الحالية بكل تحققها (ومنها QR/Lot عند الطلب) → حفظ مرجع الحركة والاستخدام → التالي**

---

## Workflow G — يحتاج صيانة / مخزوني

**يحتاج صيانة → مخزوني → اختيار الصنف → الكمية → استخدام نفس آلية الصرف الحالية للمستودع الفرعي بكل متطلباتها (QR/Lot/الكمية/التحقق) → إصلاح → تم الإصلاح**

PM V2 لا تنفذ خصمًا مباشرًا من المخزون ولا تبني مسار صرف بديل.

---

## Workflow H — يحتاج صيانة / طلب مواد

**يحتاج صيانة → طلب مواد → اختيار الصنف → الكمية → إرسال → طلبات معلقة**

الحالة الأولى:

**بانتظار المستودع**

---

## Workflow I — المستودع / المادة متوفرة

**طلب مواد → المادة متوفرة → صرف/تحويل للفريق بنفس آلية المستودع الحالية بكل متطلباتها → issued_to_team → المهمة جاهزة للإصلاح**

ثم:

**طلبات معلقة → مهامي اليوم / متابعة إصلاح**

---

## Workflow J — المستودع / شراء خارجي

**طلب مواد → غير متوفرة → المستودع يبدأ طلب شراء خارجي داخل PM V2 → Adapter PM V2 ينشئ/يربط بلاغ الجسر → Path B الحالي → المستخدم المخول أصلًا يكمل Purchase Order**

لا يتم تعديل Path B ولا إضافة صلاحية إنشاء PO لدور `warehouse` كجزء من PM V2.

يجب حفظ الربط الكامل:

`Task → Task Item → Material Request → Bridge Ticket/Item → Purchase Order`

---

## Workflow K — متابعة الشراء

PM V2 تعرض حالات مبسطة فقط:

**قيد الشراء الخارجي**
→ **تم الشراء وبانتظار الاستلام**
→ **تم الاستلام وبانتظار الصرف**
→ **تم الصرف للفريق**

---

## Workflow L — التذكير

الفني من طلبات معلقة:

**تذكير**

النظام يسجل التذكير ويرسل التنبيه حسب الخدمة المعتمدة دون كتابة رسالة يدوية.

---

## Workflow M — إنهاء الزيارة

**آخر بند → ملخص → رئيس المهمة → المشاركون → فني من فريق آخر اختياري → اعتماد وإنهاء الزيارة**

إذا يوجد معلق:

`task = pending_followup`

إذا لا يوجد معلق:

يمكن إغلاق المهمة عند استيفاء كل البنود.

---

## Workflow N — متابعة الإصلاح

بعد صرف القطعة:

**مهامي اليوم → متابعة إصلاح → تنفيذ → تم الإصلاح → تسجيل المادة/النتيجة → إنهاء زيارة متابعة**

يمكن أن يكون فريق الزيارة مختلفًا عن الزيارة الأولى.

---

## Workflow O — الترحيل

إذا كانت المهمة `ready_followup` ولم تنفذ اليوم:

- لا تنشأ مهمة جديدة.
- نفس المهمة تظهر في اليوم التالي حتى الإغلاق.

---

## Workflow P — الإغلاق النهائي

يغلق فقط إذا:

- لا يوجد task item غير محلول.
- لا يوجد material request نشط/معلق.
- كل زيارات التنفيذ المطلوبة انتهت.

ثم:

`task.status = completed`
