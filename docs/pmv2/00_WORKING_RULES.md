# قواعد العمل الملزمة — PM V2

## 1. حماية النظام الحالي

النظام الحالي يعمل لدى العميل، لذلك:

- ممنوع تغيير أي Workflow قائم خارج PM V2.
- ممنوع تعديل سلوك البلاغات الحالية.
- ممنوع تعديل Workflow المشتريات أو Path B.
- ممنوع تعديل منطق المخزون أو المستودعات القائمة.
- ممنوع تعديل بيانات المستخدمين/الفنيين الأساسية.
- ممنوع تغيير جداول النظام القائم بغرض تكييفها مع PM V2.
- ممنوع حذف الوحدة القديمة أثناء مرحلة البناء.

PM V2 هي التي تتكيف مع النظام الحالي، وليس العكس.

## 2. أسلوب البناء

- الوحدة الجديدة مستقلة.
- الجداول الجديدة تحمل بادئة `pmv2_`.
- ملفات Backend الجديدة توضع في نطاق PM V2 مستقل.
- ملفات Frontend الجديدة توضع في نطاق PM V2 مستقل.
- Jobs الجديدة تكون خاصة بـ PM V2.
- Integration مع النظام الحالي يتم من خلال Adapters/Services واضحة.

## 3. التغييرات المسموحة خارج PM V2

فقط تغييرات تسجيلية/Additive ضرورية لتشغيل الوحدة، مثل:

- تسجيل Route جديد.
- إضافة عنصر Menu جديد.
- تسجيل Router جديد.
- إضافة Migration جديد.
- إضافة import/registration محدود.

ولا يجوز أن تغير هذه الإضافات سلوك وظيفة قائمة.

## 4. قاعدة "أجب عليا"

إذا قال المستخدم **أجب عليا**:

- تتم الإجابة والنقاش فقط.
- لا يعدل الكود.
- لا تنشأ ملفات كود.
- لا تنفذ Migration.
- لا تنفذ إصلاحات.
- لا تنشأ حزمة Patch.

الاستثناء: المعلقات التي يقول المستخدم صراحة **ذكرني بها لاحقًا** توثق فورًا.

## 5. قاعدة "نفذ الآن"

التنفيذ الفعلي يبدأ فقط عند قول المستخدم **نفذ الآن** أو أمر صريح مكافئ لا يحتمل اللبس.

## 6. قاعدة التوثيق المستمر

أي عمل يتم يجب أن يترك أثرًا واضحًا في التوثيق:

- ماذا تغير؟
- لماذا؟
- ما الملفات؟
- ما الاختبار؟
- هل ظهرت مشكلة؟
- هل توجد مهمة متبقية؟
- ما الخطوة التالية؟

## 7. قاعدة حزم التعديل

كل تعديل برمجي يسلم في ZIP صغير:

- يحتوي فقط على الملفات الجديدة أو المعدلة.
- يحافظ على المسار النسبي نفسه داخل المشروع.
- يحتوي على التوثيق المحدث.
- لا يحتوي ملفات غير مرتبطة بالتعديل.
- يحتوي Manifest يوضح كل ملف والغرض منه.

مثال:

```text
PMV2_PATCH_001.zip
├── client/
│   └── src/...
├── server/
│   └── routers/pmv2/...
├── drizzle/
│   └── xxxx_pmv2_....sql
└── docs/
    └── pmv2/
        ├── 06_IMPLEMENTATION_STATUS.md
        ├── 07_ISSUES_AND_FIXES.md
        ├── 10_RELEASE_NOTES.md
        └── PATCH_MANIFEST.md
```

## 8. قاعدة الأخطاء

أي خطأ مهم يوثق في `07_ISSUES_AND_FIXES.md` ويشمل:

- وصف المشكلة.
- متى ظهرت.
- السبب الجذري.
- طريقة الإصلاح.
- الملفات المتأثرة.
- الاختبار الذي أثبت الحل.
- الإجراء الذي يمنع تكرار المشكلة.

## 9. قاعدة قاعدة البيانات والتنفيذ اليدوي

عند الحاجة مستقبلًا إلى إضافة أو تعديل في قاعدة البيانات:

- لا ينفذ المساعد أوامر قاعدة البيانات مباشرة.
- يرسل الأمر المطلوب للمستخدم يدويًا، خطوة واحدة في كل مرة.
- ينفذ المستخدم الأمر على القاعدة ويرسل النتيجة.
- بعد مراجعة النتيجة فقط يتم إرسال الأمر التالي.
- عند أي تغيير في Schema يجب تحديث ملف الـSchema داخل المشروع وتسليمه للمستخدم ليستبدله مكان النسخة القديمة.
- لا يتم تجاوز هذه القاعدة حتى لو كانت Migration مقترحة أو بسيطة.

## 10. قاعدة المعلقات

إذا قال المستخدم:

**ذكرني لاحقًا بـ...**

تسجل مباشرة داخل:

`pending/PENDING_ITEMS.md`

ولا تحذف عند إنجازها؛ تنقل إلى قسم **تم الإغلاق** مع تاريخ الإغلاق وكيف تم التعامل معها.
