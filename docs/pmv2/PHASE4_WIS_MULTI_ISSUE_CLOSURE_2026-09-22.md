# PM V2 / Inventory — إغلاق الصرف المخزني المتعدد WIS

**التاريخ:** 2026-09-22  
**الحالة:** ✅ **CLOSED / PASS**  
**نطاق الإغلاق:** شاشة الصرف المخزني المتعدد المستقلة + السجل + الطباعة + قواعد التكرار/الرصيد حتى Patch 129.  
**Phase 4:** ما تزال **IN PROGRESS**؛ هذا الإغلاق لا يعني إغلاق Phase 4 بالكامل.

## 1. القرار التشغيلي النهائي

- الشاشات الأربع الحالية للصرف الفردي تبقى **كما هي** ولا يتم تحويلها أو ربطها تلقائيًا بـWIS.
- شاشة **الصرف المخزني المتعدد** مخصصة للصرف المجمع فقط.
- WIS واحد = **مخزن مصدر واحد + فني مستلم واحد + مادتان/سطران على الأقل + عدة Lots/مواد عند الحاجة**.
- WIS هو مستند التجميع والطباعة، بينما حركات Inventory/Lot/Delivery الداخلية تظل محافظة على سجلاتها المرجعية.
- لا يسمح بإصدار WIS ببند واحد؛ الصرف الفردي يستمر من الشاشات الحالية.

## 2. ما تم إنجازه

### Patch 124 — WIS foundation
- إنشاء شاشة مستقلة للصرف المخزني المتعدد.
- إضافة ترقيم WIS مستقل.
- تنفيذ صرف عدة بنود ضمن عملية واحدة مع إعادة استخدام منطق الصرف المخزني القائم.
- حفظ مستند WIS وإتاحته في Documents Center.
- إنشاء جداول WIS التشغيلية: `warehouse_issue_batch_number_counter`, `warehouse_issue_batches`, `warehouse_issue_batch_items`.

### Patch 125 — Cost target
- دعم الموقع والقسم والأصل كجهة مستفيدة/تحميل تكلفة.
- الموقع والقسم إلزاميان، والأصل اختياري.
- تعبئة تلقائية من السياق عند توفره، مع إمكانية التحديد اليدوي عند عدم توفر السياق.

### Patch 126 — Materials grid
- تنظيم مواد WIS في Grid واضح ومستقر بدل العرض غير المنظم.

### Patch 127 — History + print
- إضافة تبويب **سجل الصرف** داخل شاشة WIS.
- عرض الموقع والقسم في العرض/الطباعة.
- فتح وطباعة مستندات WIS من السجل.

### Patch 128 — Multi-only rule
- تغيير الاسم في Sidebar وعنوان الصفحة إلى **الصرف المخزني المتعدد**.
- منع الاعتماد إذا كان WIS يحتوي على بند واحد فقط.
- إبقاء مسارات الصرف الفردي الحالية بدون تغيير.

### Patch 129 — Repeat same Lot by cost target
- السماح بتكرار نفس الصنف ونفس الـLot لنفس الفني داخل WIS إذا اختلف واحد على الأقل من: **الموقع أو القسم أو الأصل**.
- منع التكرار إذا تطابقت جهة التكلفة بالكامل.
- التحقق من مجموع كميات كل أسطر نفس الـLot وعدم السماح بتجاوز الرصيد المتاح.
- إظهار الجهة المستفيدة بوضوح في جدول المواد.

## 3. قبول Runtime الفعلي

تم قبول الحالات التالية يدويًا على البيئة الفعلية:

- إنشاء WIS فعلي سابقًا (`WIS-2026-000001`) وظهوره في Documents Center مع فتح/طباعة ناجحين.
- **سجل الصرف** يعمل بصورة صحيحة.
- الموقع والقسم يظهران في عرض/طباعة WIS.
- مع بند واحد فقط: زر **اعتماد وصرف** غير مفعل.
- بعد إضافة بند ثانٍ: الزر يتفعل.
- تكرار نفس الـLot مع اختلاف جهة التكلفة: **مسموح**.
- صرف فعلي ناجح لهذه الحالة: **`WIS-2026-000004`**.
- تكرار نفس الـLot مع نفس الموقع + القسم + الأصل: **ممنوع**.
- تجاوز مجموع كميات نفس الـLot للرصيد المتاح: **ممنوع**.
- تمت طباعة `WIS-2026-000004` في اختبار القبول النهائي بدون الإبلاغ عن مشكلة.
