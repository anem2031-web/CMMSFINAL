## ISSUE-001 — خطر تكرار المواقع داخل PM V2

- **الحالة:** تم حسم الاتجاه التصميمي — التنفيذ لم يبدأ.
- **اكتشف:** 2026-09-05
- **المشكلة:** التصميم القديم اقترح `pmv2_location_groups` و`pmv2_locations` رغم وجود `sites` و`sections` و`assets` في البرنامج الحالي.
- **الخطر:** إنشاء Source of Truth موازٍ يؤدي لاختلاف الأسماء والحالات والتقارير وربط البلاغات والمشتريات.
- **القرار:** لا تنشأ مواقع PM V2 افتراضيًا. تستخدم PM V2 Targets موجودة عبر Adapter.
- **الاختبار المطلوب:** Phase 0 يجب أن يفحص البيانات الفعلية ويثبت هل Target = Site أو Section أو Asset في كل حالة.
- **منع التكرار:** Existing Capability Audit إلزامي قبل أي جدول جديد.

## ISSUE-003 — Schema Drift محتمل في Specialty على Users

- **الحالة:** مفتوح — تحقق مطلوب قبل التنفيذ.
- **اكتشف:** 2026-09-05
- **المشكلة:** يوجد Migration يضيف `specialty`, `specialtyEn`, `specialtyUr` إلى `users`، بينما تعريف `users` في `drizzle/schema.ts` بالنسخة المفحوصة لا يتضمن هذه الحقول.
- **الخطر:** الاعتماد على Schema غير مطابق للقاعدة الفعلية أو إنشاء Migration خاطئة.
- **الحل الحالي:** لا تعتمد PM V2 على هذه الأعمدة قبل فحص قاعدة البيانات الفعلية ومطابقة migrations/schema.
- **طريقة التحقق:** أوامر DB يرسلها المساعد يدويًا للمستخدم عند بدء التنفيذ/الفحص المصرح به.
- **منع التكرار:** Reality Check للSchema قبل ERD/Migration.

## ISSUE-005 — لا يوجد Department Master عام ظاهر في النسخة المفحوصة

- **الحالة:** مفتوح للتحقق من DB.

- **المشكلة:** الهيكل المتفق عليه يبدأ بـ"القسم الحالي"، لكن الـSchema المفحوص يظهر `users.department` كنص، بينما `sections` مكاني و`ticket_departments` خاص بالبلاغات.

- **منع التكرار:** لا ينشأ جدول Department داخل PM V2 دون إثبات أن النظام الحالي لا يملك Source of Truth صالحًا واعتماد المستخدم.

## ISSUE-006 — اختلاف دلالة ready_followup عن `delivered_to_requester` في Path B

- **الحالة:** مفتوح جزئيًا — اتجاه تكامل موثق ويحتاج Freeze نهائي.
- **اكتشف:** 2026-09-05 أثناء فحص Path B والمخزون.
- **المشكلة:** PM V2 تعتبر المهمة جاهزة بعد وصول المادة إلى مخزن الفريق، بينما Path B الحالي يعتبر مادة PO مسلمة للمستفيد النهائي عند `delivered_to_requester`.
- **الخطر:** إغلاق/تقدم أحد المسارين قبل الآخر أو فقدان الربط بمادة PO.
- **الحل المرشح:** Warehouse Transfer إلى مخزن الفريق يجعل PM V2 `ready_followup`؛ ثم Follow-up يصرف المادة فعليًا عبر `issueDelivery` مع `purchaseOrderItemId`/Bridge reference عند الحاجة، فيكمل Path B طبيعيًا.
- **الاختبار المطلوب:** إثبات المسار على بيانات/خدمات النظام الحالية قبل إغلاق Phase 0 ثم Regression في Phase 11/14.
- **منع التكرار:** تخزين Purchase Order Item reference على Material Request Item وعدم الاعتماد على PO header فقط.

## ISSUE-008 — تعذر تشغيل Baseline TypeScript/Test في بيئة الفحص الحالية

- **الحالة:** قيد بيئة التنفيذ، وليس خطأ كود مثبت.
- **اكتشف:** 2026-09-05.
- **المشكلة:** لا توجد `node_modules` ولا binary محلي لـ`pnpm`. محاولة Corepack لجلب pnpm تحتاج الشبكة وفشلت بسبب DNS/عدم توفر الوصول الخارجي.
- **الأثر:** لم يمكن تشغيل `pnpm check` أو `pnpm test` في نسخة الفحص الحالية.

- **الاختبار اللاحق:** قبل إغلاق أي Phase برمجية يجب تشغيل Check/Tests في بيئة المشروع التي تحتوي Dependencies.
- **منع التكرار:** تسجيل نتيجة الاختبار الفعلية في `09_TESTING.md` وعدم اعتبار Static inspection بديلًا للRuntime tests.



## ISSUE-009 — DB Reality Check الأول على `users` أعاد empty set

- **الحالة:** مفتوح — جارٍ التحقق، لا يوجد Root Cause مثبت بعد.
- **اكتشف:** 2026-09-05 أثناء Phase 0 / Step 0.2a.
- **المشكلة:** استعلام `INFORMATION_SCHEMA.COLUMNS` باستخدام `TABLE_SCHEMA = DATABASE()` و`TABLE_NAME = 'users'` للأعمدة المطلوبة أعاد `empty set` رغم أن الاستعلام نفسه نجح.
- **ما لا يجوز استنتاجه:** لا يعني ذلك وحده أن جدول `users` غير موجود أو أن كل الأعمدة غير موجودة؛ قد يكون الاتصال على Schema مختلفة، أو `DATABASE()` لا تشير إلى قاعدة التطبيق، أو توجد فروقات أخرى يجب إثباتها.
- **الأثر:** لا يمكن تجميد External IDs أو Users Adapter أو Specialty/Department references قبل معرفة Schema الفعلية.
- **الإجراء التالي:** استعلام Read-only يثبت اسم قاعدة البيانات الحالية ووجود جدول `users` في نفس السياق قبل أي استعلام أعمدة إضافي.
- **منع التكرار:** كل تصميم FK/Adapter يعتمد على DB Reality Check مثبت، وليس على `drizzle/schema.ts` أو Migration منفردة فقط.
