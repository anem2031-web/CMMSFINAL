# PM V2 — مركز التوثيق الرسمي

> المرجع الرسمي لوحدة **المهام اليومية والصيانة الدورية — PM V2**.

## الحالة الحالية

- المرحلة الحالية: **Phase 0 — Existing Capability Audit + Design & Integration Freeze**.
- Phase 0 / Step 0.1 (فحص القدرات الموجودة من الكود): **مكتمل**.
- Phase 0 / Step 0.2 (DB Reality Check): **بدأ**؛ أول Query على `users` نجح لكنه أعاد `empty set`، والتحقق من Schema الفعلية مستمر.
- Phase 0 ما زالت **مفتوحة** لحين Reality Check من قاعدة البيانات وتثبيت ERD النهائي.
- PM V2: **لم يبدأ تنفيذ الكود بعد**.
- قاعدة البيانات: **لا توجد جداول أو Migration منفذة لـ PM V2**.
- الوحدة القديمة: موجودة كما هي ولم يتم المساس بها.
- القرار المعماري الحالي: **PM V2 وحدة مستقلة معماريًا داخل نفس البرنامج (Bounded Module / Modular Monolith)**.
- PM V2 لا تكرر Master Data أو الخدمات الموجودة؛ تستخدمها عبر Adapters واضحة.
- التنفيذ البرمجي لا يبدأ إلا بأمر المستخدم الصريح: **نفذ الآن**.

## القرار المعماري المختصر

PM V2 تملك منطقها الخاص فقط، مثل:

- التخصصات التنظيمية.
- فرق الصيانة وربط الأعضاء.
- Checklists والتكرار.
- برامج الصيانة.
- Due Engine / Scheduler.
- المهام وبنودها.
- الزيارات والمتابعة والإغلاق.
- حالة طلب المادة من منظور PM V2.
- Audit التشغيلي الخاص بالوحدة.

وتعيد استخدام الموجود في البرنامج بدل نسخه، مثل:

- `sites`
- `sections`
- `assets`
- `users`
- `warehouses`
- `catalog_items`
- `inventory` وInventory Transactions / Lots
- QR/Barcode infrastructure
- البلاغات عند الحاجة إلى Bridge
- Path B
- Purchase Orders
- خدمات رفع الصور/الملفات المناسبة

## الهيكل التنظيمي المعتمد

**القسم الحالي → التخصص → الفريق → الأعضاء**

مع التمييز بين:

- **القسم الحالي:** مفهوم موجود أصلًا في البرنامج ولا تنشئ PM V2 نسخة منه.
- **التخصص:** كيان تنظيمي جديد داخل PM V2 مثل كهرباء/سباكة/ميكانيكا.
- **الفريق:** فريق صيانة داخل التخصص.
- **الأعضاء:** مستخدمون/فنيون موجودون أصلًا في `users`.
- **مسؤول التخصص:** دور إشرافي ثابت داخل PM V2.
- **رئيس المهمة:** مسؤول عن زيارة معينة فقط، وليس منصبًا إداريًا ثابتًا.

> مهم: `sections` في البرنامج تمثل **أقسامًا مكانية داخل الموقع**، ولا يجب خلطها مع القسم الوظيفي أو التخصص.

## قواعد لا يجوز تجاوزها

1. لا يتم تغيير Workflow قائم حتى يتوافق مع PM V2.
2. PM V2 تتوافق مع النظام الحالي، وليس العكس.
3. لا يتم إنشاء نسخة PM V2 من Master Data موجودة أصلًا دون مبرر موثق ومعتمد.
4. أي تكامل مع النظام الحالي يمر عبر Adapter/Integration Boundary واضح.
5. لا يتم الخصم المباشر من المخزون من PM V2؛ تستخدم آلية المخزون الحالية.
6. Path B يبقى كما هو وصلاحياته الحالية تبقى كما هي.
7. الوحدة القديمة لا تحذف أثناء البناء.
8. كل مرحلة لها Acceptance Gate ولا يتم الانتقال قبل نجاحها.
9. أي تعديل قاعدة بيانات يرسل للمستخدم SQL يدويًا خطوة بخطوة، والمستخدم ينفذه ويرسل النتيجة.
10. عند أي تعديل Schema يتم تحديث ملف Schema وتسليمه ضمن Patch.
11. كل تعديل فعلي يسلم ZIP صغيرًا بالملفات المعدلة فقط وبنفس هيكل المشروع.
