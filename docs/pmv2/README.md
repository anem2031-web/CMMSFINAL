# PM V2 — مركز توثيق المهام اليومية والصيانة الدورية

> **هذا الملف هو نقطة البداية الإلزامية لأي جلسة تطوير جديدة تخص PM V2.**

## الحالة الحالية

- المرحلة: **التوثيق والتصميم قبل التنفيذ**
- الوحدة القديمة: موجودة كما هي ولم يتم المساس بها.
- PM V2: لم يبدأ تنفيذ الكود بعد.
- قاعدة البيانات الجديدة: تصميم مقترح فقط، ولم يتم إنشاء Migration بعد.
- آخر قرارات التكامل: استخدام آلية الصرف/التحويل الحالية للمخزون بكل متطلباتها، وربط الشراء الخارجي بالمهمة الأصلية عبر بلاغ الجسر وPath B دون تغيير صلاحيات Path B الحالية.
- المرجع التشغيلي: `01_PLAN.md`
- المرجع الفني: `02_ARCHITECTURE.md` و`03_DATABASE.md`
- حالة التنفيذ: `06_IMPLEMENTATION_STATUS.md`
- المعلقات: `pending/PENDING_ITEMS.md`
- الأخطاء والحلول: `07_ISSUES_AND_FIXES.md`

---

# قواعد لا يجوز تجاوزها

1. **عدم المساس بالنظام الحالي أو تغيير أي Workflow قائم.**
2. PM V2 تُبنى بجداول وملفات خاصة بها قدر الإمكان.
3. المستخدمون والفنيون والمخازن والمخزون والمشتريات وPath B يتم **استخدامها وربطها كما هي**، ولا يعاد بناؤها داخل PM V2.
4. إذا احتاج PM V2 وظيفة من نظام قائم، يتم عمل Adapter/Integration من داخل PM V2 بدل تغيير النظام القائم.
5. أي تعديل خارج نطاق PM V2 يجب إيقافه وشرحه للمستخدم قبل التنفيذ، ولا يتم إلا بأمر صريح.
6. الوحدة القديمة لا تحذف أثناء البناء. حذفها يكون مرحلة مستقلة بعد نجاح PM V2 وفحص الاعتماديات.
7. كل تعديل برمجي في PM V2 يجب أن يصاحبه تحديث التوثيق.
8. كل حزمة تعديل تسلم داخل ZIP صغير يحافظ على **نفس هيكل مجلدات المشروع** ويحتوي فقط على الملفات الجديدة/المعدلة والتوثيق المحدث.
9. أي مشكلة أو قرار أو خطأ أو ملاحظة مهمة يتم توثيقها فورًا في الملف المناسب.
10. أي شيء يطلب المستخدم: **"ذكرني فيه لاحقًا"** يسجل مباشرة داخل `pending/PENDING_ITEMS.md`.
11. أي تعديل مطلوب على قاعدة البيانات لا ينفذه المساعد مباشرة: يرسل أوامر SQL يدويًا خطوة بخطوة، ينفذها المستخدم ويرسل النتيجة، ثم يرسل المساعد الخطوة التالية. وعند أي تغيير Schema يجب تحديث ملف الـSchema وتسليمه ضمن الحزمة المناسبة.

# معنى أوامر المستخدم أثناء التطوير

## "أجب عليا" / "اجب عليا"

تعني:

**إجابة ونقاش فقط. لا تنفيذ ولا تعديل كود ولا إنشاء/استبدال ملفات.**

الاستثناء الوحيد:
إذا قال المستخدم أيضًا **"ذكرني لاحقًا"** بمشكلة أو ملاحظة أو مهمة، يتم توثيقها في `pending/PENDING_ITEMS.md` لأن هذا توجيه دائم متفق عليه.

## "نفذ الآن"

تعني:

يمكن بدء التنفيذ الفعلي حسب آخر خطة معتمدة، مع الالتزام بجميع قواعد السلامة والتوثيق والحزم.

إذا لم يقل المستخدم **"نفذ الآن"** فلا تبدأ تعديل الكود.

# قاعدة تحديث التوثيق

بعد كل تنفيذ فعلي يجب تحديث الحد الأدنى التالي:

- `06_IMPLEMENTATION_STATUS.md`
- `08_DECISIONS.md` إذا اتخذ قرار جديد
- `07_ISSUES_AND_FIXES.md` إذا ظهرت مشكلة
- `09_TESTING.md` إذا تم اختبار شيء
- `10_RELEASE_NOTES.md`
- `pending/PENDING_ITEMS.md` إذا تم إغلاق أو إضافة معلق

ولا تعتبر المهمة مكتملة إذا تم تعديل الكود دون تحديث التوثيق.
